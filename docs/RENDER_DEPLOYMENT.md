# Deploying Grimoire to Render

Grimoire is a React (frontend) + FastAPI (backend) + MongoDB app. This guide
deploys the backend as a **Render Web Service**, the frontend as a **Render
Static Site**, and uses **MongoDB Atlas** for the database.

A ready-to-use [`render.yaml`](../render.yaml) Blueprint is included at the repo
root so you can deploy both services in one step.

---

## 1. Set up MongoDB (Atlas — recommended, free tier)

Render does not host MongoDB directly, so use the free **MongoDB Atlas** tier.

1. Create an account at <https://www.mongodb.com/cloud/atlas/register>.
2. Create a free **M0** cluster (any cloud/region).
3. **Database Access** → *Add New Database User* → create a user + password.
   Save these — they go into your connection string.
4. **Network Access** → *Add IP Address* → **Allow access from anywhere**
   (`0.0.0.0/0`). Render's outbound IPs are dynamic, so this is required on the
   free tier.
5. **Clusters** → *Connect* → *Drivers* → copy the **SRV connection string**.
   It looks like:

   ```
   mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

   Replace `<user>` and `<password>` with the values from step 3. This whole
   string is your `MONGO_URL`. The app reads `DB_NAME` separately, so you do not
   need a database name in the URL.

---

## 2. Deploy with the Blueprint (easiest)

1. Push this repo to GitHub.
2. In Render → **New** → **Blueprint** → connect the repo.
3. Render reads `render.yaml` and creates two services: `grimoire-api` and
   `grimoire-web`.
4. Fill in the environment variables marked `sync: false` (see below), then
   **Apply**.

### Environment variables

**grimoire-api (backend)**

| Key              | Value                                                                 |
|------------------|-----------------------------------------------------------------------|
| `MONGO_URL`      | Atlas SRV string from step 1                                          |
| `DB_NAME`        | `grimoire` (pre-filled)                                               |
| `JWT_SECRET`     | auto-generated by Render (or paste your own 64-char hex)              |
| `CORS_ORIGINS`   | your frontend URL, e.g. `https://grimoire-web.onrender.com`          |
| `ADMIN_EMAIL`    | admin login email (seeded on first boot)                             |
| `ADMIN_PASSWORD` | admin login password                                                 |

**grimoire-web (frontend)**

| Key                     | Value                                                     |
|-------------------------|-----------------------------------------------------------|
| `REACT_APP_BACKEND_URL` | your backend URL, e.g. `https://grimoire-api.onrender.com` (NO trailing slash, NO `/api`) |

> **Order matters for CORS:** deploy once, note the two Render URLs, then set
> `CORS_ORIGINS` (backend) and `REACT_APP_BACKEND_URL` (frontend) to each
> other's URLs and redeploy.

## 3. Deploy manually (without the Blueprint)

### Backend — Web Service
- **Root Directory:** `backend`
- **Runtime:** Python 3
- **Build Command:** `pip install -r requirements.txt`
- **Start Command:** `uvicorn server:app --host 0.0.0.0 --port $PORT`
- **Health Check Path:** `/api/health`
- Add the backend env vars from the table above.

### Frontend — Static Site
- **Root Directory:** `frontend`
- **Build Command:** `yarn install && yarn build`
- **Publish Directory:** `build`
- Add a **Rewrite Rule**: `/*` → `/index.html` (so client-side routing works).
- Add `REACT_APP_BACKEND_URL` pointing at the backend service URL.

---

## 4. Verify

- Backend health: open `https://<your-api>.onrender.com/api/health` → should
  return `{"status":"ok"}`.
- Frontend: open `https://<your-web>.onrender.com` → the landing page loads,
  "Start building" and "Start drafting" work, and open draft lobbies appear.
- Log in with the `ADMIN_EMAIL` / `ADMIN_PASSWORD` you configured.

## Notes
- The free Render web service spins down after inactivity; the first request
  after idle takes ~30–60s to wake. The draft lobby polling (2s) keeps an
  active session warm.
- Never commit real secrets. `render.yaml` uses `sync: false` so secret values
  live only in the Render dashboard.
